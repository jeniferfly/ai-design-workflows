# AI Design Workflows

**Practical AI-assisted workflows for design, creative production,
documentation, prototyping, and reusable systems.**

This repository explores how AI can support creative work when it is
integrated into a thoughtful, human-led process.

The focus is not simply on generating faster. It is on creating clearer
inputs, better handoffs, more intentional iteration, stronger review
practices, and reusable systems that make future work easier.

> **Human + AI \> Human or AI**

------------------------------------------------------------------------

## Why This Repository Exists

AI is most useful in creative work when it strengthens human judgment
rather than replacing it.

Used thoughtfully, AI can help:

-   reduce repetitive production work;
-   organize and structure complex information;
-   explore ideas and alternatives;
-   create cleaner project documentation;
-   accelerate prototyping;
-   support targeted design revisions;
-   preserve successful patterns;
-   turn one-off solutions into reusable workflows.

The designer still owns the decisions, creative direction, review, and
final outcome.

This repository documents some of the methods I use to make that
collaboration more intentional and repeatable.

------------------------------------------------------------------------

## Core Workflow

One of the frameworks I use for AI-assisted creative production is:

**PREP → MAP → DOCUMENT → DECIDE → BUILD → PROTECT → LEARN**

### PREP

Prepare the source material and working environment.

Use only the information necessary for the task and create clean working
sources when appropriate.

### MAP

Understand the pieces before building.

Identify assets, content relationships, existing patterns, requirements,
and dependencies.

### DOCUMENT

Turn the source material into clear requirements.

Good documentation gives both people and AI a shared understanding of
what needs to be created.

### DECIDE

Resolve important questions before production.

When the source does not establish something, surface the decision
rather than allowing AI to silently guess.

### BUILD

Create the first working solution.

When interaction or development is involved, establish functionality
before spending too much time refining visual details.

### PROTECT

Once something works, protect the approved baseline.

Future revisions should clearly identify what may change and what must
remain unchanged.

### LEARN

Capture the parts of the process that are genuinely reusable.

Successful approaches can become templates, components, standards,
prompts, or documented workflows.

## Prompting as Creative Direction

I think of a strong AI prompt less like a command and more like a
**creative brief**.

A useful structure is:

**Context → Source → Requested Change → Preservation Requirements →
Verification → Deliverable**

### Context

What are we working on, and why?

### Source

What information or reference should guide the work?

### Requested Change

What specifically needs to be created or revised?

### Preservation Requirements

What already works and must remain unchanged?

### Verification

How will we determine whether the result is correct?

### Deliverable

What should the final output look like?

This structure becomes especially useful during iterative design work
because it separates the requested change from the parts of the design
that have already been approved.

------------------------------------------------------------------------

## Targeted Revision --- Not a Redesign

One of the most useful patterns in AI-assisted design is explicitly
defining the boundaries of a revision.

Instead of:

> Fix the layout.

A stronger request might establish:

-   the specific element that needs adjustment;
-   the relationship that should change;
-   the visual reference or requirement;
-   the properties that should remain unchanged;
-   the expected behavior after the revision.

This reduces unnecessary changes and helps preserve approved work.

The principle is simple:

> **Change what needs to change. Protect what already works.**

## Markdown as a Clean Handoff Format

Markdown is plain text with lightweight structure for headings, lists,
emphasis, links, and other basic content relationships.

For AI-assisted workflows, it can provide a useful **clean handoff
format**.

Markdown can help:

-   reduce unnecessary formatting noise;
-   create structured working copies of source material;
-   make requirements easier to interpret;
-   support reusable project documentation;
-   create portable briefs, standards, and templates;
-   maintain trusted project context.

Markdown itself is **not a security feature**.

Converting information to Markdown does not automatically make that
information appropriate to share. Content still needs to be reviewed and
sanitized when necessary, and AI work should take place within an
approved environment.

## Responsible AI for Creative Work

My approach can be summarized with three simple guardrails:

### Protect

Be intentional about the information provided to AI tools.

### Verify

Review AI-assisted output for accuracy, quality, accessibility,
usability, and alignment with the requirements.

### Own

Human teams remain responsible for creative decisions and final
outcomes.

AI can accelerate the process.

Human judgment makes the work finished.

## Design Principles

The workflows in this repository are shaped by a few broader principles:

-   **Clarity over unnecessary complexity**
-   **Systems over isolated solutions**
-   **Human judgment over automated assumptions**
-   **Targeted refinement over unnecessary redesign**
-   **One clear source of truth**
-   **Reusable patterns over repeated work**
-   **Documentation when it makes the next project easier**

------------------------------------------------------------------------

## Build Once. Improve Forever.

A successful creative solution should do more than solve today's
problem.

When something works, I look for the part worth preserving:

-   a component;
-   a template;
-   a workflow;
-   a prompt structure;
-   a design pattern;
-   a documented decision;
-   a reusable lesson.

The goal is not to automate creativity.

The goal is to build better systems around creative work so people can
spend more time on the judgment, ideas, and details that matter.

**Build once. Improve forever.**
