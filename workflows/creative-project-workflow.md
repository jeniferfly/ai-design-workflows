# Creative Project Workflow

A practical framework for AI-assisted creative production.

**PREP → MAP → DOCUMENT → DECIDE → BUILD → PROTECT → LEARN**

This workflow is designed to keep AI inside a clear, human-led creative
process. It helps reduce ambiguity, preserve good decisions, and turn
successful approaches into reusable systems.

The goal is not to add process for the sake of process. Each stage
exists to prevent avoidable rework and make the next stage clearer.

------------------------------------------------------------------------

## 1. PREP

Prepare the source material and working environment before production
begins.

### Key questions

-   What is the authoritative source?
-   What information does the task actually require?
-   Does anything need to be removed or sanitized?
-   Are we working in an appropriate, approved AI environment?
-   What existing standards, templates, or references should guide the
    work?

### Good practice

Create a clean working source rather than automatically passing along
every available document or detail.

When useful, convert source material into a lightweight format such as
Markdown so the requirements are easier to review, structure, and reuse.

**Output:** A clean, appropriate working source and clearly defined
starting point.

------------------------------------------------------------------------

## 2. MAP

Understand the pieces and their relationships before building.

Map the content, assets, dependencies, interactions, and existing
patterns that affect the solution.

### Look for

-   required content;
-   visual assets;
-   component relationships;
-   interaction states;
-   existing design patterns;
-   accessibility requirements;
-   dependencies;
-   constraints;
-   approved references.

This stage is especially useful when a project contains many moving
parts. Mapping first reduces the chance that production begins before
the problem is fully understood.

**Output:** A clear picture of what exists, what connects, and what the
solution needs to account for.

------------------------------------------------------------------------

## 3. DOCUMENT

Translate the source material into explicit requirements.

Documentation creates a shared understanding between the designer,
collaborators, and AI tools.

Useful documentation might include:

-   a creative brief;
-   requirements;
-   component specifications;
-   interaction behavior;
-   content hierarchy;
-   accessibility expectations;
-   visual references;
-   acceptance criteria.

The goal is not to document everything. Document the information that
materially improves the work.

**Output:** Clear requirements that can guide production and review.

------------------------------------------------------------------------

## 4. DECIDE

Surface unresolved decisions before asking AI to fill the gaps.

AI systems can produce convincing answers even when the source does not
establish what the answer should be. When an important decision is
unresolved, make it visible.

### Examples

-   Which visual direction should be used?
-   Is this behavior required or optional?
-   Which source takes priority when references conflict?
-   Does an existing pattern apply here?
-   What must remain unchanged?

If the source does not establish the answer, decide intentionally rather
than allowing an assumption to become an accidental requirement.

**Output:** Resolved decisions, documented assumptions, or clearly
identified questions.

------------------------------------------------------------------------

## 5. BUILD

Create the first working solution.

For interactive or technical work, establish functionality before
investing heavily in visual refinement.

For visual work, establish the core hierarchy, composition, and system
before polishing small details.

### Useful principle

**Get the system working before perfecting the surface.**

AI can assist with drafting, prototyping, structuring, transformation,
exploration, and implementation---but human judgment continues to guide
the work.

**Output:** A reviewable first working version.

------------------------------------------------------------------------

## 6. PROTECT

Once something works, protect the approved baseline.

Later revisions should clearly identify:

-   what is changing;
-   what must remain unchanged;
-   which approved version is the baseline;
-   how the requested change should be verified.

This is the foundation of targeted revision.

> **Change what needs to change. Protect what already works.**

Avoid turning a small refinement into an unnecessary redesign.

**Output:** A stable approved baseline that can be refined safely.

------------------------------------------------------------------------

## 7. LEARN

Capture the parts of the work that are genuinely reusable.

A successful project may reveal:

-   a reusable component;
-   a prompt pattern;
-   a template;
-   a design pattern;
-   a workflow improvement;
-   a better review method;
-   a documented decision;
-   a useful checklist.

Not every project needs to become a system.

The goal is to preserve the lessons that will meaningfully reduce
friction or improve quality next time.

**Output:** Reusable knowledge that makes future work easier.

------------------------------------------------------------------------

## Quick Reference

  Stage          Purpose
  -------------- ----------------------------------------------------
  **PREP**       Prepare appropriate sources and environment
  **MAP**        Understand assets, relationships, and dependencies
  **DOCUMENT**   Turn source material into clear requirements
  **DECIDE**     Resolve important gaps instead of letting AI guess
  **BUILD**      Create and validate the first working solution
  **PROTECT**    Preserve approved work during refinement
  **LEARN**      Capture patterns worth reusing
