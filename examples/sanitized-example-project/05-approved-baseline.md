# 05 --- Approved Baseline

## Approved Version

**Dashboard Concept v0.2**

Status: **Approved baseline for this example**

------------------------------------------------------------------------

## Approved Decisions

The following are now treated as established for future revisions:

-   Today's Priorities appears before Active Projects.
-   Exactly three priority tasks are shown.
-   Active Projects uses the approved project-card pattern.
-   One primary action is visually prominent.
-   Spacing---not additional decoration---separates the two main content
    sections.
-   Status communication does not rely on color alone.
-   The responsive hierarchy remains consistent between desktop and
    mobile.

------------------------------------------------------------------------

## Still Open

The project-status visualization remains intentionally unresolved.

The approved baseline does **not** establish progress bars or text
labels as a reusable standard.

------------------------------------------------------------------------

## Future Revisions

Future targeted revisions should use **Dashboard Concept v0.2** as the
baseline unless it is explicitly superseded.

Changes should identify:

-   the requested target;
-   protected properties;
-   verification criteria;
-   the new version.

------------------------------------------------------------------------

## Why Record the Baseline?

An approved baseline prevents future work from accidentally reopening
decisions that have already been reviewed.

It creates a known starting point for controlled iteration.
